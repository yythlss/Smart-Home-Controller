# HLK-LD2450 与光敏模块硬件连接和功能验证手册

## 1. 适用范围

- 工程：`xiaozhi-esp32`
- 板型：`bread-compact-wifi`
- 主控：ESP32-S3
- 固件目录：`main/boards/bread-compact-wifi/`
- 本文覆盖：HLK-LD2450 雷达、GL5528 类光敏模块的接线、烧录后日志检查、亮度校准、AI 唤醒和自动灯光验证。

当前固件已经完成以下接入：

1. 光敏模块的 AO 模拟输出接入 ADC1_CH1/GPIO2。
2. LD2450 使用独立 UART1，默认 256000 baud。
3. 雷达帧通过 `AA FF 03 00 ... 55 CC` 的目标数据帧校验后，输出目标数量、坐标、速度和距离日志。
4. 雷达检测到至少一个有效目标时，系统标记“有人”；若此前为未知或无人，会触发 AI `StartListening()`。
5. 光敏值转换为 0-100% 亮度。有人且亮度不高于 25% 时，逻辑灯光状态打开；亮度达到 35% 以上才关闭，防止阈值附近反复跳变。
6. 雷达无目标只更新 `radar_target_count=0`，不会直接执行无人关机。

第 6 条是刻意设计，不是故障。LD2450 安装在门口时，门口暂时没有人不代表屋内无人；在没有完成门内/门外坐标校准和方向计数前，直接调用无人关机不安全。

## 2. 接线前必须确认

1. 先断开 ESP32 的 USB 电源，再接线。
2. 雷达与 ESP32 必须共地。
3. 光敏模块只能用 `3.3V` 供电，AO 绝不能高于 3.3V。
4. LD2450 使用 5V 供电；雷达的 UART 逻辑必须是 3.3V。若实测 TX 空闲电平为 5V，先加分压或电平转换，禁止直接接 ESP32 GPIO11。
5. 不要把 LD2450 接到 GPIO41/42，这两个引脚已经给串口屏 UART2 使用。
6. 不要把光敏 AO 接到 GPIO1，GPIO1 已给 MQ135 使用。
7. 雷达、串口屏、舵机和扬声器共用电源时，5V 电源应保留至少 500mA 的余量；出现重启、断串口或 `Brownout detector was triggered` 时先检查供电。

## 3. 最终接线表

### 3.1 GL5528 光敏模块

常见光敏模块会有 `VCC`、`GND`、`AO`、`DO` 四个引脚。有些商家标为 `A0`、`D0`，含义相同。

| 光敏模块引脚 | 连接到 ESP32-S3 | 说明 |
| --- | --- | --- |
| `VCC` | `3.3V` | 不接 5V，避免 AO 高于 3.3V |
| `GND` | `GND` | 必须与雷达和 ESP32 共地 |
| `AO`/`A0` | `GPIO2` | ADC1_CH1，读取连续亮度值 |
| `DO`/`D0` | 不连接 | 只提供可调阈值的 0/1 信号，当前程序不使用 |

文字接线图：

```text
GL5528 VCC  ---- ESP32 3.3V
GL5528 GND  ---- ESP32 GND
GL5528 AO   ---- ESP32 GPIO2
GL5528 DO   ---- 不连接
```

如果你买到的是裸 GL5528，而不是四针模块，按下列方式连接：

```text
3.3V ---- GL5528 ----+---- GPIO2
                      |
                    10k ohm
                      |
GND ------------------+
```

ADC 节点可以额外并一个 `0.1uF` 电容到 GND，减少电源和线缆噪声。上图这种“光敏电阻接 3.3V、定值电阻接 GND”的裸元件接法通常是“越亮，ADC 原始值越大”。这不代表所有四针光敏模块都相同：当前接入的模块实测为“越暗，AO 原始值越大”，应以本手册第 9 节的实测校准为准。

### 3.2 HLK-LD2450 雷达

#### 3.2.1 先准备匹配的小间距线束

LD2450 模块端不是 `2.54 mm` 杜邦排针，不能把普通杜邦母头硬插到模块接口上。你提供的官方教程只明确了四根线的名称和线序，没有标注连接器的精确针距，因此不要只凭“看起来相近”购买 `1.0 mm`、`1.25 mm`、`1.27 mm`、`PH2.0` 或 `2.54 mm` 通用线。

购买优先级如下：

1. 首选向购买 LD2450 的店铺索要或购买“`HLK-LD2450 配套 4P 线束`”或“`HLK-LD2450 转接板`”。配套件与模块插座的外壳、防呆方向和端子尺寸匹配，风险最低。
2. 店铺没有配套件时，购买前先把模块接口正面照片和本手册的线序发给卖家，要求确认是“`LD2450 模块端 4P 插头`”，另一端为四根独立 `2.54 mm` 杜邦线或裸线。常见商品关键词可使用“`HLK-LD2450 1.25mm 4P 转杜邦线`”，但必须以卖家按照片确认可插入为准。
3. 若买到的是转接板，转接板的 LD2450 端必须明确写支持该模块，转接板的 `5V/GND/TX/RX` 再用普通杜邦线接 ESP32 即可。

收到线束后，先不接 ESP32，确认插头能自然插到底且没有松动；插不进去时立即停止，不能用力压入。线束另一端若是裸线，需要压接或焊接到 2.54 mm 杜邦端子后再接开发板。

#### 3.2.2 四芯线序

以模块丝印为准，常见引脚包括 `VCC`、`GND`、`TX`、`RX`。雷达与 ESP32 的串口必须交叉连接。

| LD2450 引脚 | 连接到 ESP32-S3 | 固件定义 | 说明 |
| --- | --- | --- | --- |
| `VCC` | `5V` | 无 GPIO | 5V 稳定供电，不从 GPIO 取电 |
| `GND` | `GND` | 无 GPIO | 与 ESP32、光敏模块、串口屏共地 |
| `TX` | `GPIO11` | `LD2450_UART_RX_PIN` | 雷达发送，ESP32 接收 |
| `RX` | `GPIO12` | `LD2450_UART_TX_PIN` | ESP32 发送，雷达接收 |

文字接线图：

```text
LD2450 VCC  ---- 5V
LD2450 GND  ---- ESP32 GND
LD2450 TX   ---- ESP32 GPIO11
LD2450 RX   ---- ESP32 GPIO12
```

固件参数：

```text
UART  : UART1
波特率: 256000
格式  : 8N1
ESP TX: GPIO12
ESP RX: GPIO11
```

无论线束颜色如何，必须按信号名称接线，不能按颜色猜测。你提供的 LD2450 教程图中，模块侧四根信号为 `5V`、`RX`、`TX`、`GND`；实际接线前仍以自己模块外壳或 PCB 丝印为最终依据。

建议在 LD2450 的 `VCC` 和 `GND` 附近并联：

```text
100uF 电解电容 + 0.1uF 陶瓷电容
```

电容的正极接 5V，负极接 GND。若没有电容，第一次可先短线测试；一旦出现雷达掉线、屏幕闪烁或 ESP32 重启，再补上。

## 4. 安装位置建议

### 4.1 光敏模块

1. 放在能代表室内总体亮度的位置，例如靠近房间入口或窗口侧墙面。
2. 不要让它正对台灯、串口屏背光、灯带或手机手电筒，否则会把局部光线当成环境亮度。
3. 不要用黑色胶带完全包裹模块；外壳可以开小孔，但应避免灰尘直接落到光敏电阻上。

### 4.2 LD2450 雷达

1. 先用临时支架或双面胶试装，不要一开始就固定打孔。
2. 安装在门内上方或门内侧墙面，正面朝主要通行方向。
3. 建议离地约 1.6-2.2m，先让雷达覆盖门口约 0.5-3m 的区域。
4. 不要紧贴金属门框，也不要正对转动风扇、摆动窗帘或走廊远处活动区域。
5. 当前首轮功能只需要检测到有效目标；门内/门外方向和人数统计要等你记录真实坐标后再配置。

## 5. 烧录前检查

1. 断开 USB。
2. 再检查一次：LD2450 的 `TX` 接 GPIO11、`RX` 接 GPIO12，不能接反。
3. 再检查一次：GL5528 的 `AO` 接 GPIO2，`VCC` 接 3.3V。
4. 所有模块 GND 与 ESP32 GND 相连。
5. 检查杜邦线没有把 5V 接进 GPIO2、GPIO11 或 GPIO12。
6. 如果用外部 5V 给 LD2450 供电，外部电源 GND 必须与 ESP32 GND 相连。
7. 先不要连接大功率灯、继电器或蜂鸣器。本阶段重点是传感器输入稳定。

## 6. 编译、烧录和串口监视

当前工程已通过本机 ESP-IDF 静态构建，生成文件为：

```text
build_codex_check/xiaozhi.bin
```

推荐继续使用你现有的 VSCode ESP-IDF 插件：

1. 打开 `E:/espwork/xiaozhi-esp32/xiaozhi-esp32`。
2. 确认目标板型仍为 `bread-compact-wifi`，不要执行 `set-target` 或 `menuconfig`。
3. 先执行 Build。
4. 连接 ESP32，执行 Flash。
5. 执行 Monitor，选择实际 USB 串口，不要固定使用历史 COM 号。

命令行方式仅作为备用：

```powershell
idf.py -p COMx flash monitor
```

其中 `COMx` 替换为设备管理器中实际的 USB 串口。

## 7. 首次上电时应看到的日志

以下日志用于确认程序已经运行到正确模块，不要求时间戳完全相同：

```text
I (...) AmbientLight: Initialized on ADC channel 1
I (...) LD2450: Initialized UART1 tx=12 rx=11 baud=256000
I (...) TestBoard: LD2450 radar task running on UART1
I (...) TestBoard: Sensor task running, interval=5000 ms
```

之后每约 5 秒会看到光敏采样：

```text
Light  : OK  raw=xxxx  brightness=xx.x%
```

雷达每约 5 秒会打印一次收包统计：

```text
LD2450 stats: bytes=xxx valid=xx rejected=x
```

在雷达视场内有人移动时，每约 1 秒最多打印一次目标详情：

```text
LD2450 targets=1
LD2450 target1 x=300 y=900 speed=-120 distance=949
```

其中 X、Y、速度和距离的符号、方向与安装方向有关，第一次只需要确认数值会随人的位置和移动变化，不要急于解释正负方向。

## 8. 雷达接线验证

### 8.1 第一步：确认有串口字节

上电后等待 5-10 秒，观察 `LD2450 stats`。

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| `bytes=0` | ESP32 没有收到任何串口字节 | 检查 5V、GND、LD2450 TX 到 GPIO11、TX/RX 是否接反、波特率 |
| `bytes` 持续增加，`valid=0` | 有数据，但没有通过当前目标帧校验 | 检查模块是否处于目标输出模式、波特率、模块版本和串口电平；保留一段日志供后续分析 |
| `valid` 持续增加，`targets=0` | 雷达帧正常，但当前没有活动目标 | 走进雷达前方 0.5-2m 范围测试 |
| `valid` 增加且 `targets>0` | 雷达接线和目标帧解析成功 | 继续做 AI、灯光和坐标验证 |

### 8.2 第二步：确认有人状态和 AI 唤醒

1. 确保 ESP32 已正常联网，音频和小智对话功能可用。
2. 人先离开雷达视场，等待 `targets=0`。
3. 从门口进入或站到雷达前方。
4. 看到 `Radar observation: targets=1` 或更大的值后，系统会把 `occupied` 更新为 `true`。
5. 若此前状态是未知/无人，串口会出现：

```text
Presence detected, opening AI microphone
```

6. 观察 AI 是否进入监听状态，或直接说一句测试语音命令。

注意：同一次持续有人不会反复调用开麦。要再次验证“从无人变有人”的触发，需要先通过 HTTP 人工设置无人，或在后续方向计数版本中完成离开事件。

## 9. 光敏模块校准与自动灯光验证

### 9.1 读取两组原始值

固件默认使用：

```cpp
#define AMBIENT_LIGHT_DARK_RAW   3300
#define AMBIENT_LIGHT_BRIGHT_RAW 300
```

本批光敏模块的实测方向是“遮光时 `raw` 上升、照亮时 `raw` 下降”。因此 `DARK_RAW` 大于 `BRIGHT_RAW` 是正确的，滤波器会把遮光换算为较低的亮度百分比。以上数值仍然只是初始估计值，不是每个模块的最终值。按下面步骤校准：

1. 保持实际安装位置不动。
2. 完全遮住光敏电阻，等待两次 `Light` 日志，记录稳定的 `raw`，记为 `dark_raw`。
3. 打开房间主灯或用自然光照亮传感器，等待两次日志，记录稳定的 `raw`，记为 `bright_raw`。
4. 修改 `config.h` 中的 `AMBIENT_LIGHT_DARK_RAW` 和 `AMBIENT_LIGHT_BRIGHT_RAW`。遮光时的稳定值填入 `DARK_RAW`，照亮时的稳定值填入 `BRIGHT_RAW`；本模块通常保持 `DARK_RAW > BRIGHT_RAW`。
5. 重新 Build、Flash、Monitor。

只要“暗”和“亮”两个值填写正确，代码允许暗值比亮值大或小，不需要额外改反向开关。不要只交换变量名而不重新烧录，否则屏幕百分比不会改变。

### 9.2 验证亮度百分比

1. 先把人放入雷达视场，使 `occupied=true`。
2. 遮住光敏模块，等待最多 5 秒。
3. 预期 `brightness` 下降，`ambient_light_percent` 下降。
4. 亮度不高于 25% 时，HTTP 状态中的 `light_on` 应为 `true`。
5. 松开遮挡或照亮传感器，直到亮度达到 35% 以上。
6. 预期 `light_on` 变为 `false`。

可在电脑上查询状态：

```powershell
$base = "http://<ESP32_IP>:8080"
Invoke-RestMethod "$base/api/state"
```

重点检查字段：

```text
has_ambient_light
ambient_light_percent
has_radar_data
radar_target_count
occupied
light_on
```

### 9.3 关于物理 LED 灯

当前工程已经维护 `light_on` 状态并支持未来注册灯光输出回调，但本阶段没有为独立照明 LED 分配 GPIO，也没有绑定大功率 LED/MOSFET。也就是说：

- 现在可以通过串口、HTTP API 和小程序状态验证自动灯光逻辑。
- 板载 GPIO48 是小智状态灯，不应直接拿来当正式照明输出。
- 真正接入独立 LED、灯带或继电器前，需要先确认其工作电压、电流和驱动器件，再注册 `SetLightOutputCallback()`。

不要把 5V/12V 灯带直接接到 ESP32 GPIO。

## 10. 雷达无目标与无人关机的当前策略

当前阶段具有如下行为：

```text
雷达检测到目标 > UpdateRadarObservation(targets > 0) > occupied=true > 可开麦、可按亮度开灯
雷达没有目标 > radar_target_count=0 > 不改变 occupied > 不关闭设备
```

这样做是为了防止：屋内有人坐着、在雷达视场外、雷达被临时遮挡或人刚通过门口时，系统误判“全屋无人”并关闭设备。

要启用可靠的无人自动关闭，需要下一阶段完成以下实测：

1. 在门内、门口和门外各走三次，记录 X/Y 坐标日志。
2. 定义门外区、过渡区、门内区。
3. 验证外到内轨迹为进入、内到外轨迹为离开。
4. 增加人数估计和至少 2-5 分钟无人延时。
5. 最好增加门磁或室内 LD2410C 作为二次确认。

在这之前，不要为了“看起来自动化”而把 `radar_target_count=0` 改成直接调用 `UpdatePresence(false)`。

## 11. 常见故障排查

| 问题 | 优先检查项 |
| --- | --- |
| 烧录后立刻重启 | 5V 供电余量、共地、舵机/屏幕/雷达同时供电、Brownout 日志 |
| `LD2450 stats: bytes=0` | 雷达 VCC/GND、雷达 TX 到 GPIO11、GPIO11/12 是否接反、模块是否上电 |
| `bytes` 增长但 `valid=0` | 波特率、模块运行模式、UART 逻辑电平、数据帧是否来自 LD2450 而不是配置模式 |
| `targets` 总是 0 | 安装距离、雷达方向、人在 0.5-2m 范围内移动、模块参数限制 |
| AI 不开麦 | 先确认 `Radar observation` 日志，再确认网络、音频、当前 AI 状态和 `StartListening` 日志 |
| 亮度始终 0% 或 100% | AO 接错、VCC 接成 5V、暗/亮校准值不合理、模块电位器设定异常 |
| 遮光后 `brightness` 上升 | `DARK_RAW` 和 `BRIGHT_RAW` 的方向写反，或仍在运行旧固件 | 本批模块应设置为“遮光原始值填 `DARK_RAW`、照亮原始值填 `BRIGHT_RAW`”，确认 `DARK_RAW > BRIGHT_RAW` 后重新 Build、Flash、Monitor |
| 光照变化但灯不变 | 先确认 `occupied=true`；开灯阈值 25%，关灯阈值 35%；当前只验证逻辑状态，不一定有物理灯输出 |
| 串口日志太多 | 当前雷达详细坐标已限制为约每秒一次，统计约每 5 秒一次；不要额外在 HMI 刷新任务中打印原始字节 |

## 12. 本阶段验证清单

完成以下项目即可认为硬件输入链路已稳定：

- [ ] ESP32 可正常 Build 和 Flash。
- [ ] 串口出现 `AmbientLight: Initialized on ADC channel 1`。
- [ ] 串口出现 `LD2450: Initialized UART1 tx=12 rx=11 baud=256000`。
- [ ] LD2450 统计的 `bytes` 持续增加。
- [ ] LD2450 统计的 `valid` 持续增加。
- [ ] 人移动时目标数量、坐标或距离发生变化。
- [ ] 光敏遮挡与照亮时 `raw` 和 `brightness` 发生合理变化。
- [ ] HTTP `/api/state` 同时显示雷达和亮度字段。
- [ ] 雷达首次检测到人时，AI 进入监听或串口打印开麦日志。
- [ ] 有人且环境暗时，`light_on=true`；环境亮到 35% 以上后，`light_on=false`。
- [ ] 雷达无目标时没有出现设备被误关的情况。
