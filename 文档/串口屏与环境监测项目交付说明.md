# bread-compact-wifi 串口屏与环境监测交付说明

本文档用于把当前 `bread-compact-wifi` 板型的串口屏界面、传感器采集、队友代码整合状态和后续开发边界交付给队友。

## 2. 当前已完成内容

- TJC 4.3 寸串口屏 UART2 通信。
- TJC 命令发送前自动 UTF-8 转 GBK，用于改善屏幕中文显示。
- DHT11 温湿度读取，已采用开漏上拉和临界区读数方案。
- MQ135 ADC 原始值读取。
- 基于 MQ135 原始值的演示级空气评分和建议文案。
- 手机式首页、软件图标入口和左右滑动/边缘热区切页的设计资源。
- 串口屏按钮、图标和滑动事件解析。
- 独立 `screen_event_task`，用于消费页面切换和滑动事件，不阻塞传感器采集。
- 工程规则已写明：开发前必须阅读工程和文档日志；每完成一阶段任务必须写交付文档。
- HTTP API 已改为 WiFi 连接成功后启动。不要把 `smart_home_http_.Start()` 放回 `CompactWifiBoard()` 构造函数，否则会在 lwIP/tcpip 未就绪时触发 `Invalid mbox` 重启。
- 小程序验证必须先验证 HTTP API，再验证微信开发者工具模拟器，最后才验证手机真机；详细步骤见 `docs/mini_program_demo/README.md` 和 `docs/phase-handoff-2026-07-06-mini-program-verification-guide.md`。
- 设备触摸事件进入控制器后会输出 `SmartHome: Apply ... output` 日志。若 monitor 只有 `Screen event`，先查事件分支；若两类日志都有但外设不动，先查接线、共地、供电和模块触发方式；若出现 `Brownout detector was triggered`，先处理供电。
- `c_air` 曲线已改为固件缓存最近 30 条空气评分，进入 page1 时发送 `cle 12,0` 再回放 `add 12,0,val`；如果曲线不显示，先确认 HMI 中 `c_air` 数字 ID 是否仍为 12。
- 手动环境模式已接入串口屏、HTTP、小程序和 MCP。串口屏事件为 `BTN,ENV,MANUAL,TOGGLE`、`BTN,ENV,SCENE,GOOD/HOT/DRY/POLLUTED`，用于验证自动模式、舒适度和建议。

当前固件不再使用 ESP32 运行时整页绘制方案。旧临时方案中的 `cls/fill/draw/xstr` 不作为默认路径；页面布局由 HMI 工程控件承载，ESP32 只负责更新控件值和切页。

## 3. 当前代码框架

```text
compact_wifi_board.cc
config.h
serial_hmi.h
serial_hmi.cc
utf8_to_gbk.h
utf8_to_gbk.cc
gbk_table.inc

串口屏设计说明.md
串口屏手动事件配置手册.md
硬件连接与软件验证步骤.md
智能家居外设接线与验证步骤.md
ui_assets/
```

文件作用：

- `compact_wifi_board.cc`：板级初始化、传感器任务、串口屏事件任务。
- `config.h`：TJC UART、DHT11、MQ135、音频和按键引脚配置。
- `serial_hmi.*`：TJC UART 初始化、GBK 转码发送、页面切换、按页控件刷新、触摸/滑动事件解析。
- `utf8_to_gbk.*`：UTF-8 到 GBK 转码。
- `gbk_table.inc`：GBK 映射表，生成数据，不手工编辑。
- `dht11_sensor.*`：DHT11 单总线读取。
- `mq135_sensor.*`：MQ135 ADC 读取和空气等级估算。
- `serial_hmi_widgets.json`：HMI 页面、控件、资源和事件契约。
- `串口屏设计说明.md`：手机式图标页面和滑动切换设计说明。
- `串口屏手动事件配置手册.md`：需要在 USART HMI 编辑器里手动配置的事件、透明热区、下载和验收清单。
- `智能家居外设接线与验证步骤.md`：7 月 5 日新增智能家居、MCP、HTTP API、小程序、空气曲线和外设的完整接线与验证手册。
- `docs/phase-handoff-2026-07-06-http-api-startup-crash-fix.md`：HTTP API 启动过早导致重启的根因、修复和复测步骤。
- `docs/phase-handoff-2026-07-06-smart-home-actuator-output-debug.md`：外设不响应时的诊断日志、触摸切换 0 档修复和 Brownout 供电排查步骤。
- `docs/phase-handoff-2026-07-06-mini-program-verification-guide.md`：小程序验证步骤细化交付文档，包含 HTTP API 预验证、微信开发者工具模拟器、手机真机预览和故障排查。
- `docs/phase-handoff-2026-07-06-air-curve-comfort-manual-env-ai.md`：空气质量曲线、舒适度/建议、手动环境输入、小程序和 AI/MCP 工具增强交付文档。
- `docs/mini_program_demo/README.md`：小程序演示工程的详细操作手册，队友实际导入和验证时优先打开。
- `ui_assets/`：当前推荐导入或复刻到 HMI 编辑器的页面背景和图标资源。

## 5. 页面和事件契约

当前推荐页面：

| 页面 | 用途 |
| --- | --- |
| `page0` | 手机式首页，展示温湿度、空气状态和软件图标 |
| `page1` | 空气评分详情，展示空气评分、空气等级、MQ135 原始值、温湿度和舒适度 |
| `page2` | 智能家居控制 |
| `page3` | AI 与设置 |

图标入口事件：

```text
BTN,PAGE,AIR_DETAIL
BTN,PAGE,SMART_HOME
BTN,PAGE,AI
BTN,PAGE,SETTINGS
```

滑动或边缘热区事件：

```text
SWIPE,LEFT
SWIPE,RIGHT
BTN,PAGE,NEXT
BTN,PAGE,PREV
```

设备控制事件：

```text
BTN,DEVICE,AIR_PURIFIER,TOGGLE
BTN,DEVICE,FAN,TOGGLE
BTN,DEVICE,HUMIDIFIER,TOGGLE
BTN,MODE,AUTO,TOGGLE
```

当前固件会记录设备控制事件日志，并已把净化、新风/风扇、加湿、自动、节能事件接入真实外设控制。

## 6. 固件刷新逻辑

启动后固件会发送：

```text
page 0
```

首页刷新示例：

```text
t_ai_state.txt="IDLE"
t_temp.txt="26.0 C"
t_humi.txt="58.0 %"
t_air_state.txt="良"
t_air.txt="良(820)"
j_air.val=75
t_advice.txt="Keep ventilation"
```

空气详情页刷新示例：

```text
t_air_score.txt="75/100"
j_air_detail.val=75
t_air_state.txt="良"
t_air_raw.txt="820"
t_temp_d.txt="26.0 C"
t_humi_d.txt="58.0 %"
t_comfort.txt="舒适"
```

说明：当前 MQ135 只提供 ADC 原始值，固件基于阈值估算等级和评分；当前没有 PM2.5、CO2、TVOC 真实浓度。旧控件 `t_pm25`、`t_co2`、`t_tvoc_level` 不再作为 page1 当前必备控件。

AI 与设置页刷新示例：

```text
t_ai_state.txt="IDLE"
t_link_state.txt="UART2 9600"
```

`SerialHmi` 会缓存最新传感器数据，切到对应页面后立即刷新当前页相关控件。

## 7. 硬件连接

TJC 串口屏：

| ESP32-S3 | TJC 串口屏 |
| --- | --- |
| GPIO41 / TX | RX |
| GPIO42 / RX | TX |
| GND | GND |
| 屏幕电源 | 按屏幕规格供电 |

当前串口参数：

```text
UART2
GPIO41 TX
GPIO42 RX
9600 baud
8N1
结束符 FF FF FF
```

DHT11：

| DHT11 | ESP32-S3 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| DATA | GPIO18 |

MQ135：

| MQ135 | ESP32-S3 |
| --- | --- |
| GND | GND |
| AO | GPIO1 / ADC1_CH0 |
| VCC | 按模块规格供电 |

注意：ESP32 ADC 输入不能超过 3.3V。如果 MQ135 模块 AO 可能输出 5V，必须先分压或做电平适配。

## 9. 实机验证顺序

1. 在 USART HMI 编辑器中按 `串口屏手动事件配置手册.md` 检查 page0-page3。
2. 把 HMI 工程编译并下载到 TJC 屏幕。
3. 只接 ESP32 与 TJC 屏幕的 TX、RX、GND 和电源。
4. 烧录 ESP32 固件并打开 monitor。
5. 确认日志出现 `[TJC] page 0`。
6. 确认 `t_temp`、`t_humi`、`t_air_state`、`j_air` 等控件刷新。
7. 点击软件图标，确认能切到空气详情、智能家居、AI 与设置页。
8. 测试左/右边缘热区或滑动事件，确认页面按顺序切换。
9. 接 DHT11，确认温湿度刷新。
10. 接 MQ135，确认空气等级和评分刷新。

## 10. 已知限制和后续工作

- MQ135 只是演示级空气质量估算，不是精确 ppm 检测。
- PM2.5、CO2、TVOC 还没有接入真实传感器，当前 page1 已改为评分页，不再显示这些浓度占位。
- 智能家居按钮事件已接入真实控制逻辑：`GPIO13` 净化 LED、`GPIO14` 加湿 LED、`GPIO21` 180°角度舵机扇叶；具体接线和验证按最新阶段交付文档执行。
- 雷达、光敏、独立灯和蜂鸣器已完成控制器接口、HTTP/MCP 联调入口和自动规则，真实驱动仍需确认硬件型号与 GPIO。
- AI 聊天显示控件尚未加入当前 HMI 契约。
- HMI 文件应继续通过 USART HMI 编辑器维护，不能二进制手改。
- 最终交付时建议同时提供 `.HMI` 和屏幕可直接下载的编译产物。
