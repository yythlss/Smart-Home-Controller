- 主控：ESP32-S3
- 编写日期：2026-07-14
- 文档用途：供本组采购硬件、接线、编写驱动、联调自动控制以及队友接续开发时使用

## 2. 当前工程状态

### 2.1 已有的软件接口

当前 `SmartHomeController` 已经提供以下接口：

```cpp
void UpdatePresence(bool occupied);
void UpdateAmbientLight(float ambient_light_percent);
```

- `UpdatePresence(true)` 表示确认有人。
- `UpdatePresence(false)` 表示确认无人。
- `UpdateAmbientLight()` 接收 `0.0～100.0` 的亮度百分比，数值越小表示环境越暗。
- 当前代码在“已知有人且亮度不高于 25%”时自动开灯。
- 当前从“无人/未知”切换到“有人”时，会调用回调打开 AI 麦克风。
- 当前一旦调用 `UpdatePresence(false)`，会立即关闭净化器、新风、加湿器和灯光。

因此，真实雷达接入前必须先解决一个关键问题：**雷达暂时没有检测到门口目标，不等于家中无人。** 不能把雷达模块的瞬时无目标状态直接传给 `UpdatePresence(false)`。

### 2.2 当前主要 GPIO 占用

以下内容来自当前板型 `config.h`：

| GPIO | 当前用途 |
| --- | --- |
| GPIO0 | 启动按键 |
| GPIO1 | MQ135 模拟量，ADC1_CH0 |
| GPIO4/5/6/7/15/16 | 音频 I2S |
| GPIO13 | 净化器模拟 LED/PWM 输出 |
| GPIO14 | 加湿器模拟 LED/PWM 输出 |
| GPIO18 | DHT11 数据线 |
| GPIO21 | 180 度舵机扇叶 |
| GPIO39/40/47 | 按键 |
| GPIO41/42 | TJC 串口屏 UART2 |
| GPIO48 | 板载状态 LED |

当前尚未给光敏传感器和雷达分配正式 GPIO。

## 3. 最终选型建议

### 3.1 光敏传感器

第一版推荐：**GL5528 光敏电阻，不使用裸光敏二极管。**

原因：

1. 当前功能只需要判断环境亮暗和生成相对亮度百分比，不要求实验室级照度精度。
2. GL5528 接一个固定电阻即可组成分压电路，ESP32-S3 ADC 可以直接采样。
3. 光敏二极管输出通常是很小的光电流，若要获得稳定电压，一般还需要运算放大器、跨阻放大电路和额外调试。
4. GL5528 的响应速度足以完成智能灯光控制，不需要光敏二极管的高速响应。
5. 成本低、容易采购，也方便课程设计现场维修和替换。

如果后续必须显示真实照度单位 `lux`，再把 GL5528 升级成 `BH1750` 数字照度模块。当前版本不建议为了显示 lux 增加 I2C 驱动和额外硬件复杂度。

### 3.2 门口雷达

按“安装在门口、检测进出方向”的需求，主雷达推荐：**海凌科 HLK-LD2450。**

选择理由：

1. LD2450 可以通过 UART 输出目标坐标、距离和运动信息。
2. 可以在软件中划分“门外区、门口过渡区、门内区”。
3. 根据目标依次经过不同区域的顺序，判断进门或出门。
4. 支持多个运动目标，适合后续研究多人连续进出。
5. 相比只输出有人/无人的模块，更符合当前“检测进出”的目标。

但 LD2450 不能单独可靠证明整个家中是否有人。推荐的完整方案是：

```text
门口 LD2450：判断进门、出门方向并维护人数估计
门磁开关：确认门确实打开，减少门外路人造成的误计数
室内 LD2410C：检测移动和静止人员，作为屋内有人状态的复核
```

如果当前经费只允许购买一个雷达，应先购买 LD2450完成门口方向检测，但“无人自动关闭”必须增加延时和容错，不能直接依据 LD2450 瞬时无目标触发。

如果需求改成只检测“有人靠近设备，自动打开麦克风”，则应改买 `HLK-LD2410C`，因为它的有人/无人输出更容易接入当前 `UpdatePresence(bool)` 接口。

## 4. 光敏方案详细说明

### 4.1 方案比较

| 方案 | 优点 | 缺点 | 是否推荐 |
| --- | --- | --- | --- |
| GL5528 光敏电阻 | 便宜、接线简单、ADC 可直接采样、适合亮暗判断 | 个体差异较大、不是准确 lux、需要校准 | 当前第一版推荐 |
| 裸光敏二极管 | 响应快、线性较好 | 信号小，通常需要运放和跨阻放大 | 不推荐用于当前版本 |
| BH1750 数字照度模块 | 直接输出 lux、重复性较好 | 占用 I2C、软件和接线更复杂 | 需要准确照度时升级 |

### 4.2 采购清单

| 名称 | 建议规格 | 数量 | 说明 |
| --- | --- | ---: | --- |
| GL5528 光敏电阻 | 常见直插型 | 1～2 个 | 多买一个备用 |
| 固定电阻 | 10kΩ，1/4W，1%或5% | 1～2 个 | 与 GL5528 组成分压 |
| 陶瓷电容 | 0.1μF | 1 个 | ADC 节点滤波 |
| 杜邦线 | 公对母/公对公按实际板子选择 | 若干 | 连接开发板 |
| 面包板 | 小型即可 | 1 块 | 首次联调使用 |

### 4.3 推荐接线

```text
ESP32 3.3V ── GL5528 ──┬──── ESP32-S3 ADC 输入
                        │
                       10kΩ
                        │
ESP32 GND ──────────────┴──── GND

ADC 输入节点再接一个 0.1μF 电容到 GND。
```

按这个方向接线：

- 环境越亮，GL5528 阻值越小，ADC 电压越高。
- 环境越暗，GL5528 阻值越大，ADC 电压越低。
- ADC 输入由 3.3V 分压产生，不得接到 5V。

候选 ADC 引脚可以从未占用的 ADC1 引脚中选择。`GPIO2 / ADC1_CH1` 可作为优先候选，但正式使用前必须确认：

1. 实际 ESP32-S3 开发板是否把 GPIO2 引出。
2. GPIO2 是否连接了板载器件。
3. GPIO2 是否会影响启动、下载或其他外设。
4. 当前模块和开发板原理图是否允许作为 ADC 输入使用。

在这些信息确认之前，不修改 `config.h`。

### 4.4 ADC 与亮度百分比换算

GL5528 个体差异明显，不建议把 ADC 原始值直接当作固定亮度百分比。应先在实际安装位置记录两个校准值：

- `raw_dark`：认为需要开灯时的较暗环境 ADC 值。
- `raw_bright`：白天或开灯后的明亮环境 ADC 值。

由于本接线方式是“越亮 ADC 越大”，可以按以下公式换算：

```text
brightness = (raw - raw_dark) × 100 / (raw_bright - raw_dark)
```

换算后把结果限制在 `0～100`：

```text
raw <= raw_dark    -> 0%
raw >= raw_bright  -> 100%
其他情况           -> 按公式线性换算
```

然后调用：

```cpp
smart_home_.UpdateAmbientLight(brightness_percent);
```

### 4.5 推荐的软件滤波

不能每读取一次 ADC 就立即开关灯，否则灯光变化、手遮挡传感器和 ADC 噪声都可能导致频繁闪烁。

建议第一版参数：

1. 每 100ms 采样一次。
2. 每组采集 10 次，去掉一个最大值和一个最小值。
3. 对剩余 8 次求平均。
4. 每 1 秒最多向控制器更新一次亮度。
5. 亮度变化小于 2% 时不更新状态。

当前代码只有一个 25% 阈值，没有开灯与关灯回差。真实硬件接入时建议改为：

```text
有人且亮度 <= 25%：开灯
亮度 >= 35%：关灯
25% < 亮度 < 35%：保持原状态
```

这样可以避免亮度在 25%附近波动时反复开关灯。

### 4.6 光敏硬件验证步骤

1. ESP32 不上电，按接线图连接 GL5528、10kΩ和 0.1μF 电容。
2. 用万用表通断档检查 3.3V 与 GND 是否短路。
3. 暂时不接 ADC，只给电路供电，用万用表测量分压节点。
4. 用手完全遮住 GL5528，记录暗环境电压。
5. 用手机手电筒照射 GL5528，记录亮环境电压。
6. 确认节点电压始终在 `0～3.3V` 内，再连接 ESP32 ADC。
7. 串口每秒打印一次 ADC 原始值、滤波值和亮度百分比。
8. 遮挡和照射传感器，确认百分比变化方向正确。
9. 通过当前 HTTP 接口查看状态，确认 `ambient_light_percent` 同步变化。
10. 最后再启用自动开灯规则，先用板载小 LED 或低功率 LED 验证，不要直接连接大功率照明灯。

## 5. LD2450 雷达方案详细说明

### 5.1 LD2410C 与 LD2450 的区别

| 项目 | HLK-LD2410C | HLK-LD2450 |
| --- | --- | --- |
| 主要用途 | 人体存在检测 | 多目标运动轨迹和坐标检测 |
| 静止人员检测 | 较适合 | 不应作为唯一静止存在依据 |
| 进出方向判断 | 不擅长 | 可以通过区域与轨迹判断 |
| 软件接入难度 | 较低 | 较高，需要解析数据帧和状态机 |
| 与当前 `UpdatePresence(bool)` 的匹配 | 直接 | 需要增加人数和方向逻辑 |
| 当前门口需求 | 只能判断门口有人 | 更符合检测进出方向的要求 |

### 5.2 LD2450 采购清单

| 名称 | 建议规格 | 数量 | 说明 |
| --- | --- | ---: | --- |
| 毫米波雷达 | HLK-LD2450 正规模块 | 1 个 | 购买时确认排针和资料 |
| 5V 稳压电源 | 为雷达预留不少于 500mA 余量 | 1 路 | 不从普通 GPIO 供电 |
| 电解电容 | 100μF，耐压不低于 10V | 1 个 | 放在雷达 5V 与 GND 附近 |
| 陶瓷电容 | 0.1μF | 1 个 | 高频去耦 |
| 杜邦线/焊接线 | 按安装距离选择 | 若干 | 最终安装不建议松动杜邦线 |
| 门磁开关 | 常闭或常开型均可，软件适配 | 建议 1 个 | 提高进出计数可信度 |
| LD2410C | 5V UART/OUT 版本 | 可选 1 个 | 用于室内存在复核 |

### 5.3 电源和串口注意事项

LD2450 常见模块使用 5V 供电。具体供电范围、接口排列和默认波特率必须以收到的模块说明书或丝印为准。

基本连接关系：

```text
LD2450 VCC  -> 稳定 5V
LD2450 GND  -> ESP32 GND，共地
LD2450 TX   -> ESP32 UART1 RX 候选引脚
LD2450 RX   -> ESP32 UART1 TX 候选引脚
```

必须注意：

1. 雷达 TX 和 ESP32 RX 必须交叉连接，雷达 RX 和 ESP32 TX 也必须交叉连接。
2. 不得把 5V UART 信号直接输入 ESP32-S3。购买后要确认 LD2450 UART 是 3.3V 逻辑；不确定时先用万用表或逻辑分析仪测量空闲电平。
3. 串口屏已使用 UART2，调试下载通常使用 UART0，因此雷达建议使用 UART1。
4. GPIO11、GPIO12可以作为 UART1 RX/TX 候选，但必须先核对开发板原理图和引脚引出。
5. 模块常见默认串口速率为 256000 baud，但正式代码必须以实际模块资料和上位机配置结果为准。
6. 雷达电源附近放置 100μF 和 0.1μF 电容，降低 Wi-Fi、扬声器和舵机动作导致的电源波动。
7. 雷达、舵机、串口屏和扬声器同时工作时，5V 电源必须有足够余量。若发生重启或 Brownout，应先检查供电，不要先修改业务代码。

### 5.4 安装位置

推荐先做临时支架，不要一开始就固定打孔。

1. 安装在门内上方或门侧，模块正面朝向主要通行区域。
2. 建议离地约 1.6～2.2m，具体高度根据门宽和雷达视场实测调整。
3. 避免正对转动风扇、摆动窗帘、宠物活动区和车辆频繁经过的位置。
4. 不要让金属门框紧贴雷达天线正面。
5. 第一阶段把有效范围限制在门口约 0.5～3m，避免检测到走廊远处人员。
6. 安装后必须重新采集目标坐标，不能照搬别人的区域坐标。

### 5.5 区域划分

根据实际坐标方向划分三个区域：

```text
区域 A：门外等待区
区域 B：门口过渡区
区域 C：门内确认区
```

注意：不同安装方向下 X、Y 正负方向可能不同。必须先让一名队员按“门外 -> 门内”和“门内 -> 门外”各走三次，记录串口坐标，再确定 A、B、C 的具体边界。

推荐的方向判定：

```text
A -> B -> C：记为一次进入，人数估计 +1
C -> B -> A：记为一次离开，人数估计 -1
只进入 B 后返回原区域：不计数
只在 A 区路过：不计数
```

### 5.6 方向状态机要求

每个被跟踪目标至少保存：

```text
目标编号
当前区域
上一个稳定区域
首次出现时间
最后更新时间
本次轨迹经过的区域序列
是否已完成一次进出计数
```

建议规则：

1. 一个目标连续 3～5 帧位于同一区域后，才确认区域切换。
2. 一次轨迹完成计数后，在目标离开检测范围前不重复计数。
3. 轨迹超过 5～10 秒没有更新则超时清除，但不要因此直接判定家中无人。
4. 人数估计最小为 0，出现负数时记录异常日志。
5. 设备重启后人数应为“未知”，不能默认 0。
6. 多人紧跟通过、两人并排和中途折返必须作为单独测试项。
7. 门磁处于关闭状态时，门外人员移动默认不触发人数变化。

### 5.7 家中有人状态融合

建议最终使用以下判断：

```text
estimated_people > 0
或
室内 LD2410C 检测到有人
或
最近一次明确进入事件仍在有效保护时间内
```

满足任意一项时，认为家中有人。

只有同时满足以下条件，才允许确认无人：

```text
人数估计为 0
并且室内存在雷达持续无人
并且门口没有未完成轨迹
并且持续满足 2～5 分钟
```

确认无人后，才能调用：

```cpp
smart_home_.UpdatePresence(false);
```

确认进入时可以调用：

```cpp
smart_home_.UpdatePresence(true);
```

### 5.8 AI 自动开麦防抖

当前代码在占用状态由未知/无人变为有人时调用 `Application::StartListening()`。真实雷达接入后应增加以下保护：

1. 只在确认“进入”事件后开麦，不因目标在门口轻微移动重复开麦。
2. 增加 30～60 秒冷却时间。
3. 麦克风已经处于监听或对话状态时，不重复调用。
4. 同一次多人进入事件最多触发一次。
5. 门外路过和门内人员走近门口不触发开麦。
6. 提供串口日志，打印触发来源、轨迹和冷却剩余时间。

## 6. 推荐实施方案

### 6.1 最小演示方案

适合先把功能做出来：

```text
GL5528 + 10kΩ：检测相对亮度
LD2450：检测门口进出方向
门磁：约束只有开门时才计数
低功率 LED：演示智能开灯
```

该方案能演示进门、出门、天暗开灯和 AI 接近唤醒，但人数统计仍可能因多人并行、重启和漏检发生漂移。

### 6.2 推荐可靠方案

```text
GL5528 + 10kΩ：环境亮暗
LD2450 + 门磁：门口方向和人数估计
LD2410C：室内移动/静止存在复核
MOSFET 驱动照明 LED
有源蜂鸣器 + 三极管/MOSFET：报警输出
```

该方案更适合实现“无人自动关闭”和环境异常报警，软件可以用多种证据互相校验。

## 7. 接入代码前还需要确认的信息

### 7.1 必须确认的硬件信息

1. ESP32-S3 开发板的准确型号、模块丝印、原理图或购买链接。
2. GPIO2、GPIO11、GPIO12是否实际引出且没有板载冲突。
3. LD2450 的准确版本、引脚排列、供电范围、UART 电平和默认波特率。
4. 当前 5V 电源额定电流，以及串口屏、舵机、扬声器和雷达同时工作时是否有足够余量。
5. 门宽、门框材质、门内外可用安装距离和雷达朝向。
6. 是否允许增加门磁开关。
7. 是否只演示单人进出，还是必须支持两人连续或并排通过。
8. 是否需要在断电重启后保存人数；如果需要，应设计 NVS 保存和重启复核策略。
9. LED 是小型指示灯、5V灯带、12V灯带还是交流照明灯。
10. 蜂鸣器是有源还是无源、工作电压和最大电流。

### 7.2 必须确认的软件策略

1. 无人持续多久才关闭设备，建议第一版设置为 2～5 分钟。
2. 无人时是否关闭全部设备，还是保留空气质量异常时的低档净化。
3. 自动开灯阈值是否采用 25%开、35%关。
4. 雷达进入后是否自动开麦，以及冷却时间采用 30 秒还是 60 秒。
5. 设备重启且人数未知时，默认保持设备状态还是进入保守模式。
6. 人数计数异常时是否在串口屏和小程序显示“占用状态待确认”。
7. 串口屏是否增加“有人/无人/未知、人数估计、环境亮度、雷达状态”控件。

### 7.3 AI 联网能力仍需确认的信息

小智平台如果已经提供内置新闻工具，当前不要求用户再提供 RSS 地址。RSS 桥接只保留为备用功能。

仍需确认：

1. 当前智能体是否已经启用内置新闻和天气工具，而不仅是平台有该能力。
2. 工具在智能体中的实际名称、权限和可调用范围。
3. 天气工具是否能根据用户所在城市查询，还是需要固定城市。
4. AI 是否能同时读取室内 MCP 状态和平台天气结果，再生成综合建议。
5. 平台是否支持定时任务或主动消息；这决定“定时环境播报”是否能使用动态 TTS。
6. 新闻播报需要几条、每条多长、是否限定类别和可信媒体。
7. 平台工具调用失败时的降级文案，例如“暂时无法获取新闻，不影响本地环境控制”。

## 8. 推荐开发顺序

1. 获取开发板原理图，完成剩余 GPIO 和电源预算表。
2. 只连接 GL5528，完成 ADC 采样、滤波、校准和亮度百分比输出。
3. 使用 HTTP `/api/context` 验证现有智能灯光规则，再接真实亮度。
4. 单独给 LD2450 供电，用厂商工具确认模块正常并记录串口参数。
5. ESP32 只做 LD2450 原始帧接收和十六进制日志，不立即接自动控制。
6. 完成数据帧解析，连续打印目标编号、坐标和距离。
7. 采集真实门口进出轨迹，划分 A、B、C 区域。
8. 完成进出方向状态机和人数估计，但先只打印结果。
9. 加入门磁和异常保护，完成“未知/有人/无人”状态融合。
10. 将可靠的最终状态接入 `UpdatePresence()`。
11. 增加 AI 开麦冷却和对话状态检查。
12. 最后再启用无人关机，且先把无人确认延时设为 5 分钟观察。
