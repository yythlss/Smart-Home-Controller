## 4. 内容事实边界

报告和 PPT 必须以当前工程已实现内容为准，不夸大为未完成的功能。

### 4.1 硬件与传感

- 主控：ESP32S3。
- 本地显示：TJC 串口屏，UART2，ESP32 TX GPIO41 接屏幕 RX，ESP32 RX GPIO42 接屏幕 TX，9600 8N1。
- 温湿度：DHT11，GPIO18。
- 空气质量：MQ135，GPIO1 / ADC1_CH0。
- 净化控制：红色 LED，GPIO13，PWM 亮度表示档位。
- 加湿控制：蓝色 LED，GPIO14，PWM 亮度表示档位。
- 新风控制：GPIO21 舵机带动扇叶，当前源码为 0 到 180 度范围内按档位往复摆动。

### 4.2 本地串口屏

串口屏用于现场查看和控制，页面包括：

- 首页：温度、湿度、空气状态、空气评分、建议、AI 状态。
- 空气详情页：空气评分、MQ135 原始值、温湿度、舒适度、近期空气质量曲线。
- 智能家居控制页：净化、新风、加湿、自动、节能。
- AI 与设置页：AI 状态、连接状态、手动环境场景。

说明串口屏时重点讲“现场不用手机也能看、能操作”，不要写成单纯装饰屏。

### 4.3 小程序与 HTTP API

小程序通过局域网 HTTP 访问 ESP32S3，接口包括：

- `GET /api/state`：读取当前状态。
- `GET /api/history`：读取近期历史。
- `POST /api/device`：控制净化、新风、加湿档位。
- `POST /api/mode`：控制自动、节能模式。
- `POST /api/environment`：手动输入或切换环境场景。

报告中应说明小程序适合家庭、宿舍、教室、小型办公室等局域网场景，用于手机端查看和控制。

### 4.4 AI 与 MCP 语音控制

当前工程包含两条能力：

- 固件内注册 `self.home.*` 工具，用于设备端 MCP 控制。
- 外部桥接服务 `tools/xiaozhi_mcp_bridge/smart_home_bridge.py` 将小智平台 MCP 调用转发到 ESP32 HTTP API。

报告中要把 AI 控制讲成“语音入口 + 工具调用 + HTTP 转发 + ESP32 执行动作”的链路，不写成虚泛的智能大脑。

### 4.5 自动模式与节能模式

- 自动模式根据温度、湿度、空气评分和手动环境场景调整净化、新风、加湿。
- 节能模式关闭自动模式和所有执行器。
- 手动环境场景包括舒适、高温、干燥、污染，便于现场展示自动控制逻辑。

说明时重点讲清楚“自动不是替用户做神秘判断，而是把阈值规则落到实际执行器动作上”。

## 5. 报告写作要求

### 5.1 语言要求

语言要像学生团队自己写的技术报告，清楚、自然、具体。优先使用短句和可验证的描述。

推荐写法：

- “系统检测到空气评分偏低时，会提高净化和新风档位。”
- “串口屏负责现场查看和触摸控制，小程序负责手机端远程操作。”
- “AI 语音控制本质上是把口语指令转换成工具调用，再由桥接程序转发给 ESP32。”

避免写法：

- “极具价值的全链路无缝闭环。”
- “赋能未来智慧生活生态。”
- “引领行业范式跃迁。”
- “仅用于竞赛演示。”
- “演示级。”
- “原型演示级。”
- “最难的是。”

如需说明限制，改成当前版本边界或后续扩展：

- “当前版本保存最近 30 条采样记录，后续可扩展到云端数据库。”
- “当前空气质量使用 MQ135 原始值和评分展示，后续可加入 PM2.5、CO2 等更细分传感器。”

## 7. PPT 设计要求

### 7.1 页数与时间

PPT 控制在 8 到 10 页。视频加 PPT 总体展示时间控制在 5 分钟以内。

建议答辩节奏：

- 视频 3 分钟以内。
- PPT 补充讲解 2 分钟以内。

### 7.2 视觉风格

PPT 要精美但不过于花哨。

颜色不超过三种：

- 深墨绿：标题、主线、关键框。
- 浅灰白：背景、留白、表格底。
- 暖橙：强调动作、状态变化、重要数字。

不使用大量渐变、发光、复杂动画。配图形式要多样：

- 实物照片页。
- 系统架构图页。
- 三端交互对比页。
- 自动控制逻辑页。
- 应用价值页。

### 7.3 PPT 页面规划

1. 标题页  
   作品名称、定位语、核心画面。

2. 问题与应用场景  
   室内环境看不见、手动控制麻烦、老人小孩和公共空间需要更直观的空气管理。

3. 我们做了什么  
   一句话说明系统：检测空气和温湿度，本地屏显示，手机和 AI 控制，自动调节净化、新风、加湿。

4. 系统组成  
   展示硬件、串口屏、小程序、AI/MCP 的架构。

5. 串口屏现场交互  
   展示串口屏页面和能操作的功能。

6. 小程序控制  
   展示状态读取、设备档位、自动/节能、历史空气质量。

7. AI 语音控制  
   展示语音指令到 MCP 工具，再到 ESP32 API 的过程。

8. 自动与节能模式  
   展示系统如何根据环境状态调整设备，节能如何关闭执行器。

9. 测试与完成情况  
   用表格说明传感器、屏幕、小程序、AI、执行器、自动模式已验证的情况。

10. 应用价值与扩展  
   家庭、宿舍、教室、小办公室；后续可扩展云端、更多传感器、真实家电控制。

每页文字少，讲稿承担详细解释。PPT 不写长段落。

## 8. 视频建议

视频重点放作品演示，不做全 PPT 讲解。建议结构：

1. 0 到 15 秒：开场，展示实物整体和一句话定位。
2. 15 到 45 秒：展示串口屏首页、空气详情页和曲线。
3. 45 到 85 秒：展示串口屏控制净化、新风、加湿、自动、节能。
4. 85 到 125 秒：展示小程序读取状态、切换设备档位、查看历史。
5. 125 到 165 秒：展示 AI 语音控制，例如打开净化器二档、开启自动模式、模拟污染环境。
6. 165 到 180 秒：展示系统价值和扩展方向，收束到家庭、宿舍、教室、小办公室应用。

讲述逻辑：

- 先讲问题：室内环境变化不直观，控制分散。
- 再讲作品：用 ESP32S3 把感知、显示、控制、AI 入口连到一起。
- 再讲演示：现场屏、手机、语音三种入口都能控制同一套设备状态。
- 最后讲价值：低成本、可视化、可扩展，适合小空间环境管理。
